# Banking Data Pipeline

Учебный проект по Data Engineering: загрузка синтетических
банковских данных из CSV в PostgreSQL с проверками качества
и аналитической витриной.

## Стек

- Python
- PostgreSQL
- Psycopg 3
- SQL
- Git

## Данные

Все данные сгенерированы и не относятся к реальным клиентам:

- 1 000 клиентов;
- 2 000 счетов;
- 10 000 транзакций.

## Как работает пайплайн

1. Читает CSV-файлы клиентов, счетов и транзакций.
2. Загружает данные в PostgreSQL.
3. Обновляет существующие записи через ON CONFLICT DO UPDATE.
4. Выполняет четыре проверки качества данных.
5. Фиксирует изменения при успешной проверке.
6. При ошибке откатывает транзакцию и записывает ошибку в лог.

Повторная загрузка тех же файлов не создаёт дубликаты.
Каждый запуск обрабатывает CSV целиком.

## Проверки качества

- У каждого клиента ровно два счёта — правило тестового набора.
- Валюта транзакции совпадает с валютой счёта.
- Дата транзакции не предшествует регистрации клиента.
- Количество операций в витрине совпадает с исходной таблицей.

## Аналитическая витрина

SQL-представление daily_transactions содержит показатели
по дням и валютам:

- общее количество операций;
- количество неуспешных операций;
- сумму успешных платежей;
- сумму успешных пополнений.

## Логирование

Логи сохраняются в logs/pipeline.log и выводятся в терминал.
Содержат этапы загрузки, результаты проверок, количество
записей, длительность запуска и подробности ошибок.

## Проверенное поведение

- Повторная загрузка сохраняет количество записей.
- Искусственно вызванная ошибка откатывает изменение данных.
- После устранения ошибки пайплайн успешно запускается снова.
